## Spacing Scale

All spacing uses `dp` values at multiples of 4, consistent with Material 3 spacing tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4.dp | Icon-to-text gaps, inline padding, badge offsets |
| sm | 8.dp | Compact element spacing, card internal gaps, grid spacing |
| md | 16.dp | Default element spacing, card padding, content padding |
| lg | 24.dp | Section padding, photo grid spacing |
| xl | 32.dp | Layout gaps, empty-state horizontal padding |
| 2xl | 48.dp | Major section breaks (e.g., photos section after notes) |
| 3xl | 64.dp | Page-level spacing (not expected in this phase) |

**Exceptions:**
- Touch targets: minimum 48.dp (Material 3 standard) for all interactive elements (FAB, IconButtons, photo thumbnails)
- Card thumbnail width: 80.dp (established in Phase 2, `CardThumbnail.kt`)
- Position slot min height: 120.dp (established in Phase 2, `PositionSlot.kt`)

**Source:** Existing code uses 4.dp, 8.dp, 12.dp, 16.dp, 32.dp. This formalizes the scale.

## Typography

M3 default `Typography()` is currently used (`Type.kt` is empty). This phase defines the specific roles:

| Role | M3 Default | Weight | Line Height | Usage |
|------|-----------|--------|-------------|-------|
| Display | `displayLarge` (~57.sp) | 400 | 1.12 | Empty state icon replacement (✨ → mystical symbol) |
| Heading | `headlineSmall` (~24.sp) | 400 | 1.33 | Reading title in detail, section headers ("Cards", "Notes", "Photos") |
| Body | `bodyLarge` (~16.sp) | 400 | 1.50 | Reading list item titles, reading notes, position names, card names |
| Label | `bodyMedium` (~14.sp) | 400 | 1.43 | Date stamps, position meanings, helper text, "Tap to select" hints, search placeholder, photo captions |
| Label emphasis | `labelLarge` (~14.sp) | 500 | 1.43 | Section labels, reversed badge text |

**Weights:** Exactly 2 weights used across the app — **400 (regular)** for all body/heading text, **500 (medium)** for labels only. No bold (700) or semibold (600) — the dark theme achieves hierarchy through color and size, not weight.

**Source:** Existing code uses `headlineSmall`, `titleMedium`, `bodyLarge`, `bodyMedium`, `labelLarge`, `labelSmall`. This formalizes the scale and restricts weights.

## Color

**Source:** Color.kt — colors already defined. This section formalizes the 60/30/10 application.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#121212` (DarkBackground) | App background, Scaffold content area |
| Secondary (30%) | `#1E1E1E` (DarkSurface), `#2C2C2C` (DarkSurfaceVariant) | Cards, position slots, bottom sheets, photo thumbnails |
| Accent (10%) | `#9C27B0` (DarkPrimary) | Assigned slot borders, FAB, active search indicator, primary buttons |
| Highlight | `#FFD700` (DarkSecondary) | Reversed card badge, gold accent on key interactive elements |
| Destructive | `#CF6679` (DarkError) | Delete confirmation dialog, error states only |
| Text primary | `#E0E0E0` (onBackground/onSurface) | Body text, titles |
| Text secondary | `#B0B0B0` (onSurfaceVariant) | Helper text, dates, labels, placeholder text |

**Accent (`#9C27B0`) reserved for:**
1. Assigned position slot borders (2.dp solid)
2. FloatingActionButton background
3. Primary action buttons (Save, Confirm)
4. Active search bar indicator (cursor, active underline)
5. Selected card highlight in CardPickerBottomSheet

**Highlight (`#FFD700`) reserved for:**
1. Reversed card "R" badge background
2. Star/mystical decorative elements (if used)
3. Empty state decorative icon

**Destructive (`#CF6679`) reserved for:**
1. Delete confirmation dialog text and icon
2. Error state icons and borders
3. Never used for any non-destructive action

**Source:** Color.kt, D-60 (dark theme colors already defined — polish is about application, not new colors).

## Component Specifications

### Photo Section (ReadingDetailScreen)

**Location:** Below notes section, above date stamp. D-33.

**Layout:**
- Section header: "Photos" (`headlineSmall`, `onSurfaceVariant`)
- Photo grid: `LazyHorizontalGrid` with 3 columns, 8.dp spacing, 80.dp thumbnail height
- "+" button: First item in grid, 80.dp square, `DarkSurfaceVariant` background, `Add` icon, 48.dp touch target
- Tap photo: Opens full-screen viewer (see below)
- Long-press photo: Shows "Remove photo?" confirmation dialog. D-36.

**Photo Viewer:**
- Full-screen `Dialog` (not bottom sheet — photos need full context). D-35 discretion resolved.
- DarkBackground fills entire screen
- Photo displayed with `ContentScale.Fit`, centered
- Close button: Top-right `IconButton` with `Close` icon
- Delete button: Top-right `IconButton` with `Delete` icon (if in edit mode or long-press triggered)
- Swipe gesture: Horizontal swipe to navigate between photos (if multiple attached)

**Add Photo Flow:**
- Tap "+": Shows bottom sheet with two options — "Take Photo" (camera) and "Choose from Gallery" (Photo Picker). D-34.
- Camera: `ActivityResultContracts.TakePicture()` intent
- Gallery: Android Photo Picker API (no storage permissions). D-37.

### Search Bar (ReadingListScreen)

**Layout:**
- Search field replaces or sits below TopAppBar title when active. D-46.
- Implementation: `OutlinedTextField` with `Search` leading icon, `Clear` trailing icon
- Real-time filter: `MutableStateFlow<String>` in ReadingListViewModel, filters readings as user types. D-47, D-50.
- Search matches: title, notes, card names, date (formatted string). D-48.
- Clear button: Resets search query to empty string. D-49.
- No results state: "No readings match your search" (`bodyLarge`, `onSurfaceVariant`, centered)

**Visual states:**
- Default: TopAppBar with title "Drawn", FAB visible
- Active search: TopAppBar title replaced by search field, FAB hidden (or search field sits below TopAppBar)
- Search with results: Filtered list displayed
- Search with no results: Empty state with "No readings match your search"

### Edit Mode (ReadingDetailScreen)

**Entry:** Edit `IconButton` (pencil icon) on TopAppBar. D-38, D-39.

**Visual changes when edit mode active:**
- TopAppBar gains two trailing actions: "Save" (text button, DarkPrimary) and "Cancel" (text button, onSurfaceVariant). D-41.
- Title becomes editable `OutlinedTextField` (was static `Text`)
- Notes become editable `OutlinedTextField` (was static `Text`)
- Position slots become tappable to reassign cards using existing CardPickerBottomSheet. D-42.
- Reversed toggle available on each assigned card slot. D-53.

**Exit:**
- Save: Calls `ReadingRepository.updateReading()`, exits edit mode, shows brief confirmation. D-64.
- Cancel: Discards changes, exits edit mode, restores original values.

### Reversed Card Toggle

**Interaction:** Tap assigned card in position slot to toggle upright/reversed. D-51.

**Visual treatment:**
- Reversed card: Card image displayed with `rotationZ = 180f` (upside-down flip). D-52 discretion resolved — flip is more intuitive than badge.
- Reversed badge: Small gold (`#FFD700`) "R" badge in top-right corner of card thumbnail, 16.dp diameter circle.
- Upright card: Normal orientation, no badge.
- Toggle available in: wizard (CardAssignmentStep) and reading detail edit mode. D-53.

### Delete Reading

**Entry:** Trash `IconButton` on ReadingDetailScreen TopAppBar. D-43.

**Confirmation:** AlertDialog with title "Delete reading?", descriptive body, "Delete" (error-colored) and "Cancel" buttons. D-44.

**After delete:** Navigate back to reading list. D-45.

### Theme Polish (D-55 through D-59)

**Card shadows:** All cards (reading list items, position slots) use M3 `CardDefaults.cardElevation()` with default elevation (1.dp resting, 3.dp dragged). No custom shadow values.

**Rounded corners:** M3 default shapes — `small` (4.dp) for chips/badges, `medium` (12.dp) for cards, `large` (16.dp) for bottom sheets, `extraLarge` (28.dp) for dialogs.

**Visual hierarchy:**
- Primary content: `onSurface` (#E0E0E0)
- Secondary content: `onSurfaceVariant` (#B0B0B0)
- Tertiary/hints: `onSurfaceVariant` with 0.7 alpha

**Gradients/star background:** Subtle radial gradient from `#1A1A2E` (center) to `#121212` (edges) on the ReadingListScreen background only — not on every screen to avoid visual noise. Implemented via `Canvas` with `Brush.radialGradient`. D-58 discretion resolved — keep it minimal, one screen only.
