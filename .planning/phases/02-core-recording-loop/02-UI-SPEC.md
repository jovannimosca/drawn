## Spacing Scale

All spacing uses `dp` units. Values are multiples of 4, consistent with Material 3 spacing guidelines.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4.dp | Icon gaps, card item vertical padding, inline padding |
| sm | 8.dp | Compact element spacing, label-to-field gaps |
| md | 16.dp | Default element spacing, card content padding, list item padding |
| lg | 24.dp | Section padding, wizard step content padding |
| xl | 32.dp | Layout gaps, empty state container padding |
| 2xl | 48.dp | Major section breaks, wizard step transitions |
| 3xl | 64.dp | Page-level spacing (not expected in Phase 2) |

**Exceptions:**
- Touch targets: minimum 48.dp (Material 3 requirement for all interactive elements)
- Card grid items: 80.dp width (fixed card thumbnail size, not a spacing token)
- Empty state emoji: uses `displayLarge` typography size, not spacing-controlled

**Source:** Existing ReadingListScreen.kt uses 4.dp (card vertical padding), 8.dp (spacer between error text), 16.dp (list content padding, card content padding), 32.dp (empty state padding).

## Color

Existing dark color scheme from Color.kt. Phase 2 uses these values directly — no new colors introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#121212` (DarkBackground) | Screen backgrounds, Scaffold background |
| Secondary (30%) | `#1E1E1E` (DarkSurface) / `#2C2C2C` (DarkSurfaceVariant) | Cards, list items, bottom sheet content, wizard step containers |
| Accent (10%) | `#9C27B0` (DarkPrimary) | Primary action buttons (Save Reading), selected spread highlight, FAB, active step indicator |
| Gold accent | `#FFD700` (DarkSecondary) | Reserved for Phase 3 (reversed card indicators, special highlights) — NOT used in Phase 2 |
| Destructive | `#CF6679` (DarkError) | Error state text only — no destructive actions in Phase 2 |

**Accent (`#9C27B0` / DarkPrimary) reserved for:**
1. Primary CTA button ("Save Reading")
2. Selected spread card highlight in Step 1
3. FAB icon on ReadingListScreen
4. Active step indicator in wizard progress bar
5. Text field focus indicator (M3 default behavior)

**Surface hierarchy:**
- `DarkSurface` (#1E1E1E): Cards, bottom sheet, dialog content
- `DarkSurfaceVariant` (#2C2C2C): Unassigned card slots, inactive step indicators, section dividers

**Text colors (from Theme.kt):**
- `onBackground` (#E0E0E0): Primary text on background
- `onSurface` (#E0E0E0): Primary text on surfaces
- `onSurfaceVariant` (#B0B0B0): Secondary text, hints, position meanings
- `onPrimary` (#FFFFFF): Text on primary-colored buttons

**Source:** Color.kt and Theme.kt define all values. DarkSecondary (gold) is deferred to Phase 3 per CONTEXT.md.

### Card Grid Layout (CardPickerBottomSheet)
- **Columns:** 3 columns in portrait mode
- **Card thumbnail size:** 80.dp width, aspect ratio ~2:3 (tarot card proportions)
- **Grid spacing:** 8.dp horizontal, 12.dp vertical
- **Section headers:** Full-width, `labelLarge` typography, 16.dp top/bottom padding
- **Section order:** Major Arcana → Wands → Cups → Swords → Pentacles (per D-18)
- **Within sections:** Ordered by number — Ace (1) through King (14) (per D-19)
- **Minor Arcana suit grouping:** Each suit is its own section with header (e.g., "Wands", "Cups")

### Position Slot States
| State | Visual |
|-------|--------|
| Unassigned | `DarkSurfaceVariant` (#2C2C2C) background, dashed border (1.dp), position name + meaning in `bodyMedium` / `onSurfaceVariant`, centered card icon placeholder |
| Assigned | `DarkSurface` (#1E1E1E) background, solid border (1.dp, `DarkPrimary`), card thumbnail + name, tap to reassign |

## Screen Specifications

### Screen 1: ReadingListScreen (existing, minor update)
- **Route:** `ReadingList`
- **Pattern:** Scaffold + TopAppBar ("Drawn") + FAB (+) + LazyColumn
- **FAB action:** Navigate to `AddReading` route
- **Item tap:** Navigate to `ReadingDetail(readingId)`
- **Empty state:** "✨" emoji + "No readings yet" + "Tap + to record your first reading"
- **No changes to layout** — only wire up FAB navigation (currently TODO)

### Screen 2: AddReadingScreen (new — wizard container)
- **Route:** `AddReading`
- **Pattern:** Scaffold + TopAppBar with back arrow + step indicator + content area
- **TopAppBar title:** "New Reading"
- **Navigation:** Back arrow → pops back to ReadingList
- **Step indicator:** 3 dots or "Step X of 3" text, centered below TopAppBar
- **Content:** HorizontalPager or sequential content area showing current step
- **State management:** Wizard state held in AddReadingViewModel (not nav destinations per D-27)
- **Step transitions:** "Next" button at bottom of each step (except Step 3 which has "Save Reading")
- **Step 1 → Step 2:** Requires spread selected
- **Step 2 → Step 3:** Requires all positions assigned a card
- **Back button within wizard:** Goes to previous step (not nav back)

### Screen 3: ReadingDetailScreen (new — implement TODO)
- **Route:** `ReadingDetail(readingId: Long)`
- **Pattern:** Scaffold + TopAppBar (reading title) + scrollable content
- **TopAppBar:** Shows reading title, back arrow returns to ReadingList
- **Content:**
  - Spread name as section header (`headlineSmall`)
  - Card positions in order: position name + card thumbnail + card name
  - Notes section (if present): `bodyLarge` text, 16.dp top padding
  - Date: `bodyMedium` in `onSurfaceVariant`, formatted as "Apr 3, 2026"
- **Loading state:** Centered CircularProgressIndicator
- **Error state:** "Something went wrong" + error message in error color (consistent with ReadingListScreen pattern)

## Interaction Contracts

### Wizard Flow
1. User taps FAB on ReadingList → navigates to AddReading (Step 1)
2. Step 1: User selects a spread → "Next" button becomes enabled
3. Step 2: User sees all positions for selected spread → taps each position to assign a card
4. Step 2: All positions assigned → "Next" button becomes enabled
5. Step 3: User sees auto-generated title (editable) + notes field → taps "Save Reading"
6. Save succeeds → navigates back to ReadingList (reading appears in list)
7. Save fails → shows error state with retry option

### Card Picker
1. User taps unassigned position slot → bottom sheet slides up
2. Bottom sheet shows all 78 cards in sectioned grid
3. User taps a card → bottom sheet dismisses, card assigned to position
4. User taps assigned position slot → bottom sheet opens, current card highlighted
5. User taps different card → reassigns position, bottom sheet dismisses

### Navigation
- ReadingList → AddReading: forward navigation (FAB tap)
- AddReading → ReadingList: back navigation (back arrow or save completion)
- ReadingList → ReadingDetail: forward navigation (item tap)
- ReadingDetail → ReadingList: back navigation (back arrow)
