<task type="auto">
  <name>Task 1: Configure Ktlint and Detekt for code quality</name>
  <files>.editorconfig, detekt.yml, detekt-baseline.xml, app/build.gradle.kts</files>
  <action>
    1. **Ktlint via Gradle plugin** (add to root `build.gradle.kts` or as a separate convention plugin):
       - Use `org.jlleitschuh.gradle.ktlint` plugin version 12.1.0+ (compatible with Ktlint 1.5.0)
       - Configure in `app/build.gradle.kts`:
         - Enable Android mode
         - Set Kotlin language version to "2.2"
         - Configure reporters: `plain`, `html`
         - Add `ktlint` task to `check` lifecycle task
       - Create `.editorconfig` at project root with:
         - `ktlint_standard_filename = disabled` (allow file names to follow Android conventions)
         - `ktlint_standard_import-ordering = enabled`
         - `ktlint_standard_indent = enabled`
         - `indent_size = 4`
         - `insert_final_newline = true`
         - `charset = utf-8`
         - `end_of_line = lf`

    2. **Detekt** (add to root `build.gradle.kts`):
       - Use `io.gitlab.arturbosch.detekt` plugin version 1.23.7
       - Configure `detekt { config.setFrom(files("$rootDir/detekt.yml")) }`
       - Create `detekt.yml` at project root with:
         - Enable `complexity`: `ComplexMethod`, `LongMethod`, `LongParameterList` with reasonable thresholds
         - Enable `style`: `MaxLineLength` (120 chars), `UnusedImports`, `WildcardImport`
         - Enable `potential-bugs`: `MissingWhenCase`, `RedundantElseInWhen`
         - Enable `performance`: `SpreadOperator` (warn)
         - Set `build`: `maxIssues = 0` (fail on any issue)
       - Create empty `detekt-baseline.xml` for future baseline management

    3. **Git hooks** (optional but recommended):
       - Add Ktlint `check` task as a pre-commit hook via Gradle task dependency
       - Or document in CONTRIBUTING.md that developers should run `./gradlew ktlintCheck detekt` before committing
  </action>
  <verify>
    <automated>./gradlew ktlintCheck detekt 2>&1 | tail -10</automated>
  </verify>
  <done>Ktlint and Detekt run without errors on empty project, configuration files exist at project root, quality checks integrated into `check` lifecycle task</done>
</task>

<task type="auto">
  <name>Task 2: Create GitHub Actions CI workflows</name>
  <files>.github/workflows/ci.yml, .github/workflows/quality.yml, .gitignore</files>
  <action>
    1. **`.github/workflows/ci.yml`** — Main CI pipeline:
       - Trigger: `push` to `main`, `pull_request` to `main`
       - Job: `build-and-test`
         - Runs on: `ubuntu-latest`
         - Steps:
           - Checkout code
           - Set up JDK 17 (matches compileOptions from Plan 01)
           - Set up Android SDK with `android-36`, `build-tools;36.0.0`
           - Cache Gradle dependencies (`~/.gradle/caches`, `~/.gradle/wrapper`)
           - Run: `./gradlew assembleDebug` (build verification)
           - Run: `./gradlew :app:testDebugUnitTest` (unit tests)
           - Run: `./gradlew jacocoTestReport` (coverage report — will be configured in Phase 4)
           - Upload test reports as artifacts on failure

    2. **`.github/workflows/quality.yml`** — Quality gate pipeline:
       - Trigger: `pull_request` to `main`
       - Job: `quality-check`
         - Runs on: `ubuntu-latest`
         - Steps:
           - Checkout code
           - Set up JDK 17
           - Set up Android SDK
           - Cache Gradle dependencies
           - Run: `./gradlew ktlintCheck` (code formatting)
           - Run: `./gradlew detekt` (static analysis)
           - Run: `./gradlew lintDebug` (Android lint)
           - Upload lint reports as artifacts

    3. **`.gitignore`** — Android-specific:
       - Standard Android Studio entries: `.idea/`, `*.iml`, `local.properties`, `.gradle/`, `build/`
       - OS entries: `.DS_Store`, `Thumbs.db`
       - Keystore files: `*.jks`, `*.keystore`
       - Log files: `*.log`
       - Coverage reports exclusion: `**/reports/`, `**/build/`
       - Keep: `!.gitkeep`

    These workflows lay the groundwork for TEST-02 (CI runs tests on PR) and TEST-03 (CI runs lint scans on PR). Phase 4 will add coverage threshold enforcement (TEST-04).
  </action>

  </verify>

</task>
