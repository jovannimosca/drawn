  <name>Task 3: Create AppDatabase singleton with pre-population</name>
  <files>app/src/main/kotlin/com/example/drawn/data/database/AppDatabase.kt</files>
  <action>
    Create `AppDatabase.kt` as the Room database singleton:

    1. **Database class**:
       ```kotlin
       @Database(
           entities = [
               DeckEntity::class,
               CardEntity::class,
               SpreadEntity::class,
               ReadingEntity::class,
               ReadingCardEntity::class,
               ReadingPhotoEntity::class
           ],
           version = 1,
           exportSchema = true
       )
       @TypeConverters(DateTypeConverter::class, ArcanaTypeConverter::class)
       abstract class AppDatabase : RoomDatabase() {
           abstract fun deckDao(): DeckDao
           abstract fun cardDao(): CardDao
           abstract fun spreadDao(): SpreadDao
           abstract fun readingDao(): ReadingDao
           abstract fun readingCardDao(): ReadingCardDao
           abstract fun readingPhotoDao(): ReadingPhotoDao
       }
       ```

    2. **Pre-population strategy** (per D-03, D-04, D-05):
       - Use `Room.databaseBuilder(context, AppDatabase::class.java, "drawn_database")`
       - Add `.createFromAsset("database/drawn_prepopulated.db")` — this only copies on first launch (PITFALLS.md Pitfall 11)
       - The pre-populated database file will be placed in `app/src/main/assets/database/` (created in a later step or manually by the developer)
       - For now, create the builder configuration but note that the actual `.db` file needs to be generated separately (can be done by running the app once with programmatic insertion, then exporting the DB)

    3. **Builder configuration**:
       - `.setJournalMode(RoomDatabase.JournalMode.WRITE_AHEAD_LOGGING)` for better concurrent read performance
       - `.setQueryCallback({ sql, bindArgs -> Log.d("Room", "SQL: $sql, Args: $bindArgs") }, Executors.newSingleThreadExecutor())` for debug logging only (wrap in `if (BuildConfig.DEBUG)`)
       - Do NOT use `fallbackToDestructiveMigration()` — per PITFALLS.md Pitfall 1, this would destroy user data on schema changes

    4. **Schema export**: Set `exportSchema = true` in `@Database` annotation. Room will export the schema JSON to `app/schemas/` directory. Add this to `.gitignore` exceptions (keep schema files in version control for migration reference).
  </action>
